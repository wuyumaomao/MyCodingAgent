# Codex Context Management & Memory — Research Report

**Evidence note:** `github.com`, `raw.githubusercontent.com`, `developers.openai.com` and `openai.com` were unreachable from this environment (DNS sinkhole / HTTP 403), so GitHub PR/issue content and the Rust source are cited via search-result excerpts and third-party analyses that quote them. I compensated by inspecting a **real local Codex rollout corpus** (`~/.codex/sessions`, 40+ files, one 109 MB) — marked **[local]**.

## 1. Auto-compaction

- **Trigger:** threshold = **90% of the *raw* context window**, not the usable window. `codex-rs/protocol/src/openai_models.rs` computes `(context_window * 9) / 10` then returns `min(config_limit, context_limit)` — the config knob **can only lower** it ([#40095](https://github.com/openai/codex/issues/40095), [#11805](https://github.com/openai/codex/issues/11805), [source analysis](https://news.qiniu.com/archives/1788416847658)).
- **Separate usable window:** `effective_context_window_percent` = **95%**. With a 272,000-token catalog window → usable 258,400, compact at 244,800 = **94.7% of usable** ([#40095](https://github.com/openai/codex/issues/40095)). **[local]** my corpus reports exactly `"model_context_window":258400`.
- **Knobs:** `model_auto_compact_token_limit`, `model_auto_compact_token_limit_scope` = `total | body_after_prefix` (default `total`; counts only tokens added after the compacted prefix — [commit 80fdd46](https://github.com/openai/codex/commit/80fdd4688f6fa8143488c206d4c14dc193905254)), `tool_output_token_limit`, `compact_prompt`, `experimental_compact_prompt_file` ([config sample](https://www.codex-docs.com/docs/config-file/config-sample)). No off switch is documented.
- **Two paths:** *local* — an LLM writes a **plaintext handoff summary** replacing history; *remote* — OpenAI/Azure call `POST /responses/compact` returning an **opaque `encrypted_content` blob** (`object: "response.compaction"`) ([LiteLLM](https://docs.litellm.ai/docs/response_api_compact), [compaction analysis](https://codex.danielvaughan.com/2026/04/16/codex-cli-context-compaction-tuning-long-sessions/)).
- **Persisted for the next turn: yes.** **[local]** rollout JSONL holds `{"type":"compacted","payload":{message, replacement_history, window_number, previous_window_id, window_id}}`, plus `context_compacted` events.
- **Observability:** metric `task.compact` with `type = remote | local` covering **manual and automatic**; hooks `PreCompact`/`PostCompact`; app/CLI slash command **`/compact` ("Compact the current chat's context")** ([metrics](https://www.codex-docs.com/docs/config-file/advanced), [slash commands](https://www.codex-docs.com/docs/reference/slash-commands)).
- **Emerging:** "token-budget compaction" (`compact_token_budget.rs`) skips summarization and installs a fresh window via `start_new_context_window`, with model-facing `history` and `notes` tools, behind `features.token_budget` ([analysis](https://news.qiniu.com/archives/1788416847658), [v0.153.0 `new_context`](https://codex.danielvaughan.com/2026/09/08/agentic-coding-in-the-wild-production-scale-kv-cache-workload-codex-cli/)). Beta.

## 2. What survives compaction

- **[local] `replacement_history` is user-messages-only.** In a 37 KB `compacted` record the array held only `{"type":"message","role":"user",...}` items; grep for `"type":"function_call"` inside it → **no match**. Tool calls, tool outputs, reasoning and assistant prose are dropped.
- **Pairing safety is structural, not repaired:** since no `function_call`/`function_call_output` survives, no orphans are sent. Codex also sanitizes unpaired tool calls, orphan outputs and unsupported images before each request ([analysis](https://www.cnblogs.com/ai-old-six/p/20261005)).
- **Original user requests: kept verbatim** — every `replacement_history` inspected ends with the recent user turns (including steering messages) plus the summary injected as a user message. Preamble: *"Another language model started to solve this problem and produced a summary of its thinking process…"* **[local]**
- **Files touched: not a structured field.** Observed summaries have `**Task State**`, `**Existing Implemented/Modified Components**`, `**Relevant Cache Files**`, `**Constraints**`, `**Immediate Next Step**` with explicit paths — because the prompt asks, not because a manifest is preserved **[local]**.
- **Consequences:** tool outputs are lost, so the agent re-reads files; repeated re-reads can cascade compactions ([#16812 via analysis](https://codex.danielvaughan.com/2026/04/16/codex-cli-context-compaction-tuning-long-sessions/)). System scaffolding (developer instructions, permissions, AGENTS.md, tool catalog) is **not** carried by the summary — it is rebuilt next turn.

## 3. AGENTS.md

- **Lookup** ([official AGENTS.md guide](https://www.codex-docs.com/docs/agent-configuration/agents-md)): (1) global `$CODEX_HOME/AGENTS.override.md` else `AGENTS.md`, first non-empty only; (2) project walk **root → cwd** (root = dir with `.git`, configurable via `project_root_markers`; `[]` = no parent walk), per dir trying `AGENTS.override.md`, `AGENTS.md`, then `project_doc_fallback_filenames`, at most one file per dir; (3) concatenate **root → deepest**, so nearest wins.
- **Injection:** aggregated content goes into the **first-turn instructions**; `developer_instructions` are injected *before* AGENTS.md ([config sample](https://www.codex-docs.com/docs/config-file/config-sample)). Rebuilt **per run / per new TUI session**, no cache to invalidate ([AGENTS.md guide](https://www.codex-docs.com/docs/agent-configuration/agents-md)). `/init` scaffolds it ([CLI](https://www.codex-docs.com/docs/codex/cli)).
- **Size limit: `project_doc_max_bytes`, default 32768 (32 KiB)**; beyond that no further files are added ([config sample](https://www.codex-docs.com/docs/config-file/config-sample), [AGENTS.md guide](https://www.codex-docs.com/docs/agent-configuration/agents-md)).

## 4. Session resumption

- `codex resume [ID] [--last|--all|--include-non-interactive]`, `codex exec resume`, `codex fork`, `codex archive|unarchive|delete` ([developer commands](https://www.codex-docs.com/docs/developer-commands)).
- **Reconstruction** = replaying the persisted `RolloutItem` sequence; resume transparently reads `.jsonl` or `.jsonl.zst` (materializing back to `.jsonl` on write) ([session lifecycle](https://codex.danielvaughan.com/2026/06/08/codex-cli-session-lifecycle-archive-resume-fork-rollout-persistence-management/)).
- **SQLite index** `$CODEX_HOME/state_5.sqlite` holds thread metadata (id, title, cwd, rollout path, archived_at, pinned, updated_at) and powers picker/search; it is a **projection** rebuildable from rollouts. Paginated history loads only recent turns ([v0.145](https://codex.danielvaughan.com/2026/07/26/codex-cli-paginated-thread-history-sqlite-search-resume-persisted-names-memories/)).
- **cwd:** if current ≠ saved dir, Codex asks; `tui.resume_cwd = current | session` presets it ([config sample](https://www.codex-docs.com/docs/config-file/config-sample)).
- **After compaction, resume restores the compacted window** (newest `compacted` record + later turns). Cross-surface desync is a known weak spot ([#29302](https://github.com/openai/codex/issues/29302), [#37577](https://github.com/openai/codex/issues/37577)).

## 5. History / transcript storage

- **[local]** `~/.codex/sessions/YYYY/MM/DD/rollout-<ISO-ts>-<uuid>.jsonl` plus flat `~/.codex/archived_sessions/rollout-*.jsonl`.
- **[local]** Record types: `session_meta` (session_id, `forked_from_id`, cwd, `cli_version`, `model_provider`, full `base_instructions`); `response_item` (`message`, `reasoning` with `encrypted_content`, `custom_tool_call(_output)`, `function_call(_output)`); `event_msg` (`user_message`, `agent_message`, `agent_reasoning`, `token_count`, `task_started`, `task_complete`, `context_compacted`); `turn_context` (model, effort, approval/sandbox policy, workspace roots); `world_state`; `compacted`.
- **Raw history survives compaction on disk: verified. [local]** Pre-compaction turns remain as ordinary records before the `compacted` line; nothing is deleted or rewritten (hence 109 MB files here). Corroborated by reports that post-compaction UI showed empty messages while text remained in `compacted.payload.replacement_history` ([#41954/#42311 via analysis](https://news.qiniu.com/archives/1788416847658)).
- **Caveats:** `EventPersistenceMode` = `Limited` (default: user/agent messages, token counts, turn-complete) or `Extended` (adds exec/error/MCP diagnostics, exec output truncated ~10 KB); cold rollouts Zstd-compress to `.jsonl.zst` ([session lifecycle](https://codex.danielvaughan.com/2026/06/08/codex-cli-session-lifecycle-archive-resume-fork-rollout-persistence-management/)); `[history] persistence = "save-all" | "none"`. Archived sessions have **no retention policy** — one user reported 42 GB in `~/.codex`, 28 GB of it `archived_sessions/` ([#41806 via analysis](https://news.qiniu.com/archives/1788416847658)).

## 6. Memory feature — yes, there is a native one

- **Off by default**; enable with `[features] memories = true` ([official memories guide](https://www.codex-docs.com/docs/customization/memories)).
- **Mechanism:** after a chat is idle long enough, Codex extracts observations from completed sessions into local memory files (summaries, durable entries, recent inputs, supporting evidence) under `~/.codex/memories/`; secrets redacted; background; skipped when rate-limit headroom is low. Extracted memories are **injected as developer instructions at startup** of later sessions ([memories guide](https://www.codex-docs.com/docs/customization/memories), [v0.145](https://codex.danielvaughan.com/2026/07/26/codex-cli-paginated-thread-history-sqlite-search-resume-persisted-names-memories/)).
- **Controls:** `memories.generate_memories`, `use_memories`, `disable_on_external_context`, `min_rate_limit_remaining_percent`, `extract_model`, `consolidation_model`, plus `min_rollout_idle_hours`, `max_rollout_age_days`, `max_rollouts_per_startup`, `max_unused_days`; `/memories` toggles per chat. Telemetry: `memory.phase1/phase2`, `memories.usage`, per-turn `turn.memory` (`read_allowed`, `has_citations`) ([config advanced](https://www.codex-docs.com/docs/config-file/advanced)).
- **[local]** `~/.codex/` here has `memories_1.sqlite{,-shm,-wal}` and `[features]`, but `memories/` is empty — consistent with "off by default". Retrieval format unverified first-hand. Third-party add-ons exist ([supermemory](https://github.com/supermemoryai/codex-supermemory), [Hindsight](https://hindsight.vectorize.io/blog/2026/04/08/adding-memory-to-codex-with-hindsight)).

## 7. Prompt caching / stable prefix

- **Deliberately append-only.** Static prefix order: system instructions → tool definitions → sandbox config → environment context → developer instructions → AGENTS.md → cwd/shell env → first user query; each turn **appends**, and runtime config changes are appended as new messages rather than edited in place ([prompt-caching analysis](https://codex.danielvaughan.com/2026/04/21/codex-cli-prompt-caching-maximise-cache-hits-cost-reduction/) citing OpenAI's agent-loop post).
- **Corroboration:** tool output is truncated *at ingestion* (middle truncation, head+tail) precisely because editing an old result later would invalidate the downstream prefix ([analysis](https://www.cnblogs.com/ai-old-six/p/20261005)).
- **[local]** `token_count` reports `cached_input_tokens`/`cache_write_input_tokens`; one session: `input_tokens 146,724,181` vs `cached_input_tokens 122,563,654` (~84%).
- **Known gaps:** no `prompt_cache_breakpoint` emission for GPT-5.6 ([#35300](https://github.com/openai/codex/issues/35300)); no Azure `prompt_cache_retention` ([#25604](https://github.com/openai/codex/issues/25604)).
- **Cost tension:** compaction rebuilds the prefix and **resets the cache**. Production traces: compaction in 7.8% of sessions but 44.2% of tokens, removing a median **72.8%** of context and dropping median cache hit rate **66.1 pp** ([study summary](https://codex.danielvaughan.com/2026/09/08/agentic-coding-in-the-wild-production-scale-kv-cache-workload-codex-cli/)).

## Design principles observed

- **Fixed budget, late trigger, lower-only knob:** compaction fires at a fixed fraction of the *raw* window with a hard clamp, so runs sit near-full and operators can only buy headroom.
- **Summarize the task, rebuild the harness:** the handoff carries task state only; instructions, permissions, tools and AGENTS.md are re-injected next turn — a clean task-state/policy split.
- **Lossy model context, lossless disk:** the model sees a compacted window while the rollout JSONL keeps the full raw transcript as audit/replay truth.
- **Append-only prefix as an economic constraint:** cache stability dictates truncating at ingestion rather than retroactively, and replacing a whole baseline instead of editing mid-history.
- **Durable state lives outside the window:** user requests survive verbatim in `replacement_history`; everything else worth keeping must go to AGENTS.md, notes/history tools, or an explicit summary instruction.
